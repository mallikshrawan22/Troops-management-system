🔑 Getting Started
Signing in for the first time

The first time this app runs on a device, it asks for a Device Name (e.g. "Rekha's Phone") and the shared Master Key. Everyone using this app shares the same master key — it's not a personal password, it just identifies devices that are allowed to sync.

You can tap Continue Offline instead to browse whatever data is already saved locally on this device, without signing in — useful if you just need to look something up and don't have the key handy. You won't be able to sync or save changes until you do sign in.

Patrol Mode vs Duty Management Mode

The two buttons at the top of the app switch between Patrol and Duty Management — they're almost entirely separate systems that happen to share the same troop roster. Patrol handles foot/vehicle patrols and their rotation; Duty Management handles guard posts, sentries, and shift rosters. Troops and System (bottom of the menu) are shared by both and don't change when you switch modes.

The Security PIN

If a PIN is set (System → Security PIN), it's required once per session before you can view anything other than the two dashboards or this guide. It protects logging, editing, deleting, and archiving — not just viewing. If you forget it, use the security question you set up when creating it.

🔒 Reservation System
What "reserved" actually means

The app automatically stops a troop from being double-booked — put on a patrol and a duty at the same time, or on two things that clash. You never manage this by hand; it happens invisibly every time Suggest Team or Suggest Duty builds a list. A reserved troop simply won't appear as an option — you don't need to remember to exclude them yourself.

A troop counts as reserved for a given time if any of these is true:

  • They're already logged on a duty that overlaps that time
  • They're on an unfinished Duty Draft for that time (saved but not yet logged)
  • They're on an unfinished Patrol Draft (saved but not yet logged)
  • They're currently blocked by an active Contingency Mode exclusion

Drafts count on purpose — a saved-but-not-yet-logged plan is treated as a real booking, since it usually does go on to become one.

Why the timing rules differ for Patrol vs. Duty

This part is deliberately timing-aware so it doesn't over-block — otherwise almost the entire unit could end up looking "unavailable" at once.

When planning a Patrol:

  • For a future date — nobody is blocked by duty yet; a roster that far out isn't reliable to check against.
  • For today, during the day — the whole day's Day Duty roster blocks a same-day patrol.
  • For today, after night has begun — only someone actually mid-shift right now is blocked, not the whole Night Duty roster. Most of the unit is naturally on Night Duty by then, so blocking all of them would leave almost nobody free for a night patrol.

When planning a Duty shift: the check instead looks at the real time window of the specific shift you're suggesting for — so a troop finishing today's Day Duty isn't wrongly held back from tonight's Night Duty, since the two don't actually overlap.

If someone you expected to see is missing from a suggestion, this is almost always why — check whether they're on a draft, an overlapping duty, or a Contingency exclusion before assuming something's broken.
🚶 Patrol Mode
Suggest Team — how the algorithm picks troops

Dashboard → Suggest Team builds a proposed patrol automatically. It fills specialist roles first (driver, JCO, medical, signal — whichever you tick), then fills the remaining "Others" seats by duty-%-rotation: whoever has the lowest share of patrol hours relative to their time deployed goes first, so participation stays balanced over time.

Female pairing rule: if any female troops are included, the app never assigns a single, uncompanioned female — they're only added in pairs (or as a pair alongside a female specialist), never as a lone seat. This is automatic and can't be turned off.

Once generated, you can tap any troop to Replace them with the next-best alternative, or manually pick someone specific. You can also save the whole thing as a Draft to log later instead of committing immediately.

Logging a patrol manually

Patrol Log → the ⚡ button opens a form to log a patrol by hand — pick troops, type, area, route, duration, and remarks yourself, without going through Suggest Team. Useful for anything the algorithm shouldn't decide, like an ad-hoc or emergency patrol.

Editing a patrol, re-logging, and the duplicate warning

To fix a mistake in an already-logged patrol (wrong hour, wrong troops, wrong area), always use the ✎ Edit button on that entry in Patrol Log — never re-log it as a new patrol through ⚡ Log Patrol. Editing updates the same record; re-logging creates a second, separate one.

Why this matters: a second record for the same real-world patrol counts that patrol's hours twice for every troop on it — quietly inflating their hours and participation %, even though the Patrol Log itself looks "correct" (two distinct, real rows).

The app actively guards against this: if you try to log a new patrol with the same date, same type, and mostly the same troops as one already logged, it stops you before creating it and asks whether you meant to edit the existing one instead — that's the recommended choice almost every time. You can still choose to log it as a genuinely separate patrol (e.g. two real Escort runs the same day sharing a couple of troops).

If a duplicate slips through anyway (e.g. logged from two devices before sync caught up), a ⚠ Possible duplicate patrols banner appears at the top of Patrol Log — and on the shared troop's own Profile — listing the pair with quick Edit/Delete on both, so it can be found and cleared instead of silently sitting in the stats.

The duplicate check only flags same date + same type + mostly the same troops — it won't catch, and shouldn't catch, two genuinely different patrols that happen to share a date or a troop.
Patrol Log — editing, deleting, filtering

Every logged patrol can be edited or deleted from here (PIN required if one is set). Use the filters to narrow by date range, type, or troop — helpful when preparing a report for a specific period rather than scrolling the full history.

Inactive Troops

Lists troops who haven't been on a patrol in a while, sorted by how overdue they are. Use this to spot-check that the rotation is actually reaching everyone, not just the same handful of people.

Participation Status

Shows every troop's participation percentage — their share of patrol hours against the unit average since their own deployment date, not since the unit started. A troop who joined last month is judged against last month's average, not the whole tour's.

Time off is excluded automatically for two of the three cases — no date entry needed:

Leave / Sick — flip Status to Leave or Sick in Edit Troop and save; the app quietly starts the clock. Flip Status back to Available (or anything else) and save, and it automatically banks that exact stretch as a dated exclusion — you never touch a date field for this.

Archive / Unarchive — the day archived to the day unarchived is banked the same way, automatically, the moment you unarchive someone.

Manual backfill — the only time you need the From/To date box yourself: logging time off that happened before it was tracked in the app (e.g. an old leave stretch, or an archive cycle from before this update). Add it directly in Edit Troop → Leave/Sick/Absence Record.

All three show up in the same Leave/Sick/Absence Record list on the troop's Edit screen, and every one of them is dropped out of that troop's participation window — so time off never unfairly drags their % down, and it never gets silently missed either.

Hours Ranking vs. Participation Status — which one to use

Participation Status is the fair one — each troop's hours are judged as a share of the unit's hours over that troop's own eligible window (deployment date onward, minus excluded time). This is the number that should drive fairness decisions.

Hours Ranking is a simple raw-hours leaderboard, with no window adjustment — it's analytical only, useful for a quick "who's logged the most hours overall" view, but it doesn't account for when someone joined or any excluded time, so it shouldn't be used to judge fairness on its own.

Most Active — Monthly History

A month-by-month record of the top-performing troop, based on that month's patrol hours, plus a qualifying Officer/JCO activity note where relevant. Useful for monthly recognition or when writing a handover/command report and you need "who stood out this month" without manually reviewing the whole log.

Report & Drafts

Report generates a printable summary for a chosen month/year. Drafts (top of Dashboard) holds any patrol you saved from Suggest Team without logging it yet — open a draft to review, edit, or finally commit it.
